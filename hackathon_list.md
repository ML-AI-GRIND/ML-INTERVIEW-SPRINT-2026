## Hackathon Evaluation Scorecard

Before committing, score each event from **1–5**.

| Criterion | Weight | Question |
| --- | --- | --- |
| Career Alignment | 5x | Does this strengthen ML/AI, MLOps, financial ML, cloud, or backend skills? |
| Portfolio Value | 5x | Would I proudly show the finished project to recruiters? |
| Probability of Shipping | 5x | Can I build a credible MVP before the deadline? |
| Prize / Opportunity | 3x | Are prizes, mentorship, visibility, funding, or interviews meaningful? |
| Networking | 3x | Will I meet strong engineers, companies, founders, or recruiters? |
| Cost | 2x | Can I participate without unreasonable travel or infrastructure costs? |

**Rule:** Avoid joining an event just because it exists. Prefer a smaller number of strong submissions.

## Standard Hackathon Workflow

### Phase 1 — Research
- [ ] Read rules completely
- [ ] Confirm deadline
- [ ] Confirm eligibility
- [ ] Confirm team size
- [ ] Confirm required technologies
- [ ] Check judging criteria
- [ ] Check submission format

### Phase 2 — Problem Selection
- [ ] Identify actual user
- [ ] Define one painful problem
- [ ] Write one-sentence value proposition
- [ ] Define success metric
- [ ] Identify datasets / APIs

### Phase 3 — Architecture
- [ ] Frontend
- [ ] Backend/API
- [ ] Data layer
- [ ] ML/LLM component
- [ ] Cloud/deployment
- [ ] Monitoring/evaluation

### Phase 4 — Build
- [ ] Create repo
- [ ] Create issues/tasks
- [ ] Build baseline first
- [ ] Add AI only where useful
- [ ] Deploy
- [ ] Test edge cases
- [ ] Add README

### Phase 5 — Submission
- [ ] Demo URL works
- [ ] GitHub repo accessible
- [ ] README explains architecture
- [ ] Screenshots ready
- [ ] Demo video recorded
- [ ] Pitch deck ready
- [ ] Submission form completed before deadline
